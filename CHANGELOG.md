# Changelog

## [1.8.0] — 2026-06-28

### Added

- **Auction House panel** — a Buy/Sell tool in a single window, now a standard feature for everyone (no longer dev-only). **Buy tab:** live item search (type two or more characters and results update as you go); stackable items are listed twice — once as the single and once as the stack (e.g. *Dark Crystal* and *Dark Crystal x 12*), mirroring the real in-game AH, and clicking either queues that exact variant. Queued items get a **multi-item buy queue** with per-item **Quantity / Start / Max / Increment**: the bidder walks each item's bids from the start price upward by the increment toward the max, repeating until the requested quantity is bought, paced by a configurable **throttle** so it never outpaces the server; a results log records each step. **Sell tab:** your sellable inventory (hit **Refresh** at an Auction House to pull it), a per-item **single/stack toggle + price** form whose **List** button runs the real two-step AH list handshake, and your **seven active listings** with live status (On auction / Sold / Not Sold) and price.

- **FFXIAH price links from the Auction House panel** — each queued item's name is a clickable link, and **right-clicking any item** (a search result, a queued row, or a sell-inventory item) opens that item's **FFXIAH** page in your browser to check the going rate. This is a plain link, not a scraper — set your server once on ffxiah.com and every link lands on your world's prices. The opener falls back through several methods and logs the URL to the results panel so a click always has a reachable result.

- **Floating “Sing” button for BRD** — a floating, draggable, resizable **Sing** button (same chrome as the Call Trust and Cheat Sheet buttons; its position and size persist). Click it to perform your **active** BRD song set: the addon casts each song in the set's order on packet timing and toggles the song job abilities the set calls for (Clarion Call, Troubadour, Nightingale, Soul Voice). It resolves which set is active the same way the Call Trust button does, and dims until a set is marked Active.

- **BRD Loadouts — Full Strength / Dummy grouping with a per-set Dummy toggle** — the BRD **Loadouts** tab now lists your song sets the way the Trust Sets and BLU Spellsets managers do: a green dot on the active set, the set name with its song count, and **Active/Equip · Edit · ✕** per row. Sets are split under **Full Strength** and **Dummy** section headers so dummy-song sets group apart from your real rotations, driven by a **Dummy** checkbox that now lives in the set editor (under the name field). The grouping is organizational only — it tidies the list and does not change how a set is sung; the per-song modes still drive casting. Sets are saved per character.

- **Diagnostic chat mirrored to a log file** — OmniWatch's lua-side diagnostic output is now written to a writable **`%APPDATA%\OmniWatch\omniwatch.log`** file instead of only scrolling the in-game log, so song/buff traces survive a `//lua reload` and are easy to attach to a bug report. Two commands were added for chasing song-stat issues: **`//ow debug`** and **`//ow buffdebug`** echo a one-line buff summary to game chat (the attack / accuracy / magic-haste contributions and which song sources are live) and write the full per-song breakdown to the log.

- **BRD song modes without GearSwap (optional self-equip)** — bards who don't run a GearSwap that exposes `ExtraSongsMode` can now have OmniWatch equip the gear for each song mode itself. A new per-character **`brd_songgear.lua`** (in `%APPDATA%\OmniWatch\<char>\`, written with a commented template on first run) holds a **`source`** (`gearswap` default, or `omniwatch`) and a **`sets`** table mapping each mode (none / dummy / fulllength / cheer) to slot → item. With `source = omniwatch` the singer equips the mode's set through the game's own equip path instead of messaging GearSwap — snapshotting your gear when a rotation starts and restoring it when it ends or is stopped — so the dummy-song trick works with no GearSwap at all (usually only the instrument in the `range` slot is needed). Toggle it with **`//ow brdgear [gearswap|omniwatch|reload]`**. The file is separate from `user_config.lua` so the `//ow setup` wizard can't overwrite it. **Untested:** the addon author uses Selindrile's GearSwap, so the default stays `gearswap` and the self-equip path ships unverified.

### Changed

- **Auction House panel released from the developer gate** — it's no longer hidden behind the dev sentinel. The launcher now lives under **Settings → Misc → Auction House** (directly above *Simulation mode*), and the panel title dropped its “DEV ·” prefix. Toggling and dragging are unchanged.

- **Crafting and Synergy panels merged into one tabbed window** — the two separate developer panels are now a single **Crafting / Synergy** window with a tab for each, opened from one **Settings → Developer → Crafting / Synergy** entry (the two old entries are gone). The window shares one position across tabs; **Ctrl+Shift+R** focuses the Crafting tab and **Ctrl+Shift+Y** the Synergy tab (each combo opens to its tab, switches to it if the other tab is showing, or closes the panel if it's already on that tab). The underlying craft and synergy engines are unchanged — only the two front-end windows were consolidated.

- **BRD song rotation holds its ExtraSongsMode so it stops losing a song** — while the Sing button runs a rotation it now hands GearSwap the **locked** form of each song mode (`dummylock` / `fulllengthlock` / `cheerlock`) instead of the plain value. A common Mote-style BRD GearSwap auto-resets `ExtraSongsMode` back to its default after each cast unless the value ends in `Lock`, which was silently dropping the last song of a set (you'd get three songs where you asked for four). The panel still shows the plain mode names (none / dummy / fulllength / cheer); only the value sent mid-rotation is the locked variant, and the rotation restores the idle mode when it finishes. The old dummy-skip step that could also swallow a song was removed.

- **Loadouts window remembers its position** — the shared Loadouts window position now persists across sessions and is saved the moment you finish dragging it, matching the other manager windows.

### Fixed

- **Each March labels its own buff timer (Honor / Victory / Advancing)** — the three Marches all share buff id 214, and a timer could relabel to a generic **March** when one of them dropped — e.g. casting Honor + Victory, then letting Victory fall, left the survivor reading **March** instead of **Honor March**. The buff-batch path now seeds each timer's label from the per-slot song name captured during the buff reconcile, so the marches stay distinct.

- **Stacked Marches both count toward magic haste** — a recompute triggered when the second March's gear snapshot landed could collapse the haste-source bucket for buff id 214 down to a single entry, so the first March's haste was lost (and the magic-haste / Dual Wield figure streamed to GearSwap undercounted). The source list is now reconciled against the live song names from the buff details — records for songs still active are kept and only genuinely-overwritten dummies are dropped — so both Marches' haste persists.

- **Buff timer bars drain correctly for songs that share a buff id** — stored durations were keyed by buff id alone, so a second March (214) or second Minuet (198) overwrote the first's saved full-duration and the fill ratio broke (bars stuck full or jumped). Durations are now keyed per instance (buff id + song name) and the stored peak only grows, so each song's bar tracks its own timer smoothly.

- **Attack and stats refresh the moment a song lands** — the stat recompute was gated on the set of active buff *ids* changing, so casting Valor Minuet V while Minuet IV was already up (both buff id 198) added no new id and the panel didn't recompute until something else nudged it. The recompute now also fires when the set of active song *names* changes, so the second song's attack shows immediately.

## [1.7.8] — 2026-06-16

### Fixed

- **Stats panel cell moves/hides now persist when you close setup mode** — rearranging cells or crossing them out in setup mode wrote the changes to an in-memory session layer, but exiting setup mode *discarded* that layer instead of committing it (a fully-written auto-save helper existed but was never wired into the exit path). Closing setup mode now auto-saves your moves and hides to the **current job's** layout before clearing the session layer, so they stick. The **Save as ▼** button still targets *global* or another job, and editing `omniwatch_stats_layout.json` directly still works. Auto-save is a no-op when you made no cell edits, so just repositioning panels in setup mode still saves nothing.

- **Save-as button no longer cut off when the stats panel is at the bottom of the screen** — in setup mode the panel grows downward to fit the hidden-cells tray and the **Save as ▼** button, so a panel anchored near the bottom pushed that row off-screen. When the panel sits low enough that the row would be clipped, the tray + button now render **above** the panel instead (the title and cells stay exactly where you positioned them), so the controls are always reachable.

- **Sim mode now loads your current gear reliably on open** — opening the Simulation window seeds its slots from your live-equipped gear by piggybacking on the inventory snapshot, but that snapshot is rate-limited to once per second and the gate wasn't reset on activation — so if a snapshot had gone out in the previous second, the seed was delayed (or, if that one datagram dropped in the burst, lost entirely) and the window opened without your current gear until you closed and reopened it. Activation now resets the snapshot gate so the seed fires on the very next frame, and the new Refresh button (below) re-pulls it on demand if it ever doesn't land.

### Added

- **Sim window “Refresh” button** — a new button (between Export Set and Reset) that re-syncs the sim with your live gear and forces a stats recompute, so the equipment panel and stats reflect your current picks. It re-sends the inventory snapshot — which re-seeds any slots you haven't changed from live gear (without clobbering picks you've already made) — and trips the stats signature caches so the panel recomputes immediately rather than on the next idle tick. Handy if the activation snapshot was ever dropped, or after changing several slots at once.

- **Ongoing Events — Guild Hours and Where Is NM boxes** — the events modal's fixed banner area gained a third row of two boxes between the RoE / Domain Invasion row and the transport row, and the panel grew by one row's height to fit them (no cramming). **Guild Hours** (left) cycles the nine crafting guilds every few seconds, reading the same Vana'diel clock as the header to show each as **OPEN** or **CLOSED** with an "open until 21:00" / "closed until 6:00" / "holiday (Firesday)" line — every guild's hours and elemental holiday are the static retail values (cross-checked against the guild-holiday and per-guild hour tables), so it's accurate with no network call. **Where Is NM** (right) tracks Limbus (Apollyon / Temenos) NM & ??? spawns from whereisnm.com's public API the same way the Domain Invasion box reads whereisdi: it polls the active reports on a 60-second cache, filters to your server (the Header → Server setting, shared with DI), and rotates the active entries showing the location (e.g. "Apollyon - NW Tower F4"), the NM name or ???, and how long ago it was spotted. The modal's Refresh button now refreshes it alongside the campaigns list and the DI banner.

- **Trust Sets manager** — a new **Settings → Misc → TrustSets** window for saving named groups of up to five trusts, built on the same window chrome as the BLU Spellsets manager (draggable, per-character JSON persistence, list / edit views, two-click delete). The editor lists a flat, alphabetical view of the trusts *this character owns* (the same owned list the collection checklist tracks), each row showing the trust's job; **hovering a trust shows its job plus its job abilities and traits**, read from the trust database, with a **Tips** toggle for the tooltips and a bg-wiki link on each name. Tick up to five trusts (the cap is enforced as you tick), name the set, and Save. Ticked trusts appear in a **Call Order** panel on the right, numbered in the order they'll be summoned — the order *is* the party position, so slot 1 is called first; drag a row to reorder it, or drop one with ✕. Each saved set has an **Equip** button that marks it *active* (a green dot; the button then reads **Active**) — this designates which set the **Call Trust** button (below) summons and has no in-game effect on its own. Deleting the active set, or renaming it in the editor, keeps the active marker consistent.

- **Call Trust button** — a floating, draggable, resizable button (styled like the Cheat Sheet / Super Warp buttons; toggle it in **Settings → Misc → Show Call Trust button**, position and size persist). Click it to **reconcile your party to your active Trust Set**: the overlay hands the set's trusts (in call order) to the addon, which releases (`/retr`) any party trust that isn't in the set, then summons the missing ones so the party ends up matching the set exactly. The casting is paced off the game's own `action` event — each trust is only de-queued once its cast actually completes — and it reads your real trust **limit from key items** (Magicite permit 3 / Rhapsody 4–5), **skips** trusts that are on recast or not yet unlocked (reporting which), and resolves names to spell ids via `res.spells` so new trusts work automatically. A `<char>` guard (matching the Warp / BLU-set rails) keeps a multibox call firing only on the named character; the button dims until a set is Active and shows a brief status line. *Casting/pacing approach modelled on the **Trusts** addon by from20020516 (BSD-licensed).*

## [1.7.7] — 2026-06-16

### Fixed

- **Overlay no longer crashes when a UDP port is reserved by Windows** — on some machines a port in OmniWatch's fixed 5000–5015 range is held by the Windows network stack (WinNAT / Hyper-V / WSL / Docker reserve port ranges per boot), and the overlay would die at startup with `PermissionError: [WinError 10013]` the instant it tried to `bind()` that port — most often **port 5004** (mob debuff state), which used a bare bind with no error handling so it surfaced as a raw traceback. The overlay now binds every channel to an **OS-assigned port** (`bind` on port 0), which the OS guarantees is free, so a reserved port in the old range can no longer collide. See *Changed* for how the two halves now find each other.

### Changed

- **Dynamic UDP port discovery (ephemeral binding + discovery files)** — instead of fifteen hard-coded ports, the overlay and addon negotiate their ports at runtime. The overlay binds each channel to an OS-assigned port and publishes the map to `%APPDATA%\OmniWatch\ow_ports_py.txt` (plain `channel port` lines); the addon binds its inbound command socket the same way and publishes its port to `ow_ports_lua.txt`. Each side reads the other's file and re-reads it when the contents change, so the overlay starting after the addon, a `//lua reload`, or either half restarting all re-sync on their own (a ~1 Hz content check on the addon's prerender tick; a re-read on each command send on the overlay side). Every channel keeps its own socket, handler, and wire format — the data path is byte-for-byte unchanged; only how ports are *chosen and discovered* is new. If the discovery files can't be used (e.g. no `%APPDATA%`), both sides fall back to the legacy fixed 5000–5015 ports, matching the old behavior. UDP socket ownership is now centralized in `OmniWatch.lua`: the Skillchains sub-module adopts the main addon's shared socket via `_G._ow_udp_skillchain` instead of opening its own on a fixed port, so future port changes touch one place.

## [1.7.6] — 2026-06-14

### Changed

- **Main-chunk local-variable headroom** — `OmniWatch.lua`'s top-level chunk had reached Lua 5.1's hard limit of **200 local variables per function**, so adding any new top-level `local` (e.g. a contributor's helper) broke the build with `main function has more than 200 local variables` — an error whose reported line is unrelated to the real cause. Twenty clearly-internal `_ow_*`/`ow_*` helper functions (logging, user-config I/O, sim-lookup building, DPS internals, bard-song helpers) were converted from `local function` to plain global `function`. This frees ~20 slots (main now ≈180/200) for future features and PRs. The change is mechanical and call-site-neutral: a global function is invoked identically to a local one, the names are uniquely prefixed (no shadowing), and each was verified to have a single definition. New top-level helpers should follow the same global-with-`_ow_`-prefix convention rather than adding `local`s.

### Fixed

- **Non-self Marches now count toward DW haste sources** — Trust/other-bard Marches could show correctly in the visible buff/timer path while still missing from `_ow_buff_sources[214]`, so `//ow dwtest` and the streamed `hasteinfo` value undercounted magic haste and GearSwap could pick an inflated Dual Wield bucket even with Marches active. Non-self BardSong packets are now recognized via `Bard_Songs[song_probe_id]` as a fallback when `spell_data.type` isn't `BardSong`, and a new helper resolves a configured non-self bard's March+/All Songs+ from `settings.Bards[name].song_bonus` (falling back to `ow_user_config.bards[name]`) into the existing March potency/source path. *Contributed by **gorschu** ([#26](https://github.com/BalladOfWorms/OmniWatch/pull/26)).*

- **Haste source timestamps preserved across state saves** — magic-haste source records could be restored without timing metadata, so the prune logic might treat a freshly-applied Haste/Haste II source as stale before `player.buffs` caught up, briefly undercounting magic haste and streaming an inflated `hasteinfo` to GearSwap. `_ow_save_buff_state()` now writes `cast_time`, and Haste/Haste II spell sources are stamped with `cast_time = os.time()`. *Contributed by **gorschu** ([#25](https://github.com/BalladOfWorms/OmniWatch/pull/25)).*

## [1.7.5] — 2026-06-12

### Changed

- **Warp button renamed to "Super Warp"** — the floating warp button now reads "Super" over "Warp" on two centered lines, sized identically to the Cheat Sheet button (same line spacing and padding) so the two stack consistently.

- **UI polish — soft shadows + bevel edges (BLU Spellsets window first)** — added two reusable drawing helpers: a cached soft drop shadow that floats panels above the game, and a subtle bevel (light top-left / dark bottom-right edge) that gives frames quiet depth. Applied to the BLU Spellsets window as the first surface; the helpers are built to roll across the rest of the overlay's panels next. Shadows are pre-rendered once and cached, so there's no per-frame cost.

- **UI polish — midnight background, glowing headers, matched grid spacing** — the main overlay background is now a midnight black (was dark grey). Panel header titles (EQUIPMENT, STATISTICS, and the rest) now use the same soft off-white as the BLU Spellsets title, so header text is consistent across panels. The EQUIPMENT grid gained the same inter-cell spacing the STATISTICS grid uses, so its cells breathe at the same rhythm instead of butting together — cell stride is unchanged so equipped icons fit exactly as before, and click targets follow the visible cells. The grid is also inset a few pixels from the left so the panel’s colored accent stripe stays visible beside the cells instead of being covered by the first column of gear. Panel header strips (EQUIPMENT, STATISTICS) now derive their height from the global UI scale alone via a shared helper, instead of each panel’s own body scale — so the two headers are always the same pixel height even when the panels are resized to different scales (previously a resized panel could end up with a slightly taller header than its neighbour). The chat panel’s resize grip got a larger grab zone (26px corner vs the 14px handle) so it’s no longer hard to catch on the busy panel.

### Added

- **Sim tooltips — full item cards in the gear-selection menu + food tooltips** — hovering an item in a sim slot's gear-selection dropdown now shows the same rich card as the live equipment panel (item level, level req, jobs, the description-derived stat block, and augments) instead of just a name and short augment tag. To make this work for items you aren't wearing, the sim inventory snapshot gained two streams: a per-unique-id **CARD** stream (item level / level / jobs / description stat lines — static per id, so it's deduped and sent once) and a per-copy **AUG** stream (the full augment lines for augmented copies, which the snapshot had already decoded for the short tag). Both are packed many-records-per-packet so the snapshot stays a handful of packets. Equipped items still use the live `equip_rich` card as before. "Path: A"-style opaque augments on non-equipped copies are now resolved to their real stat lines using the same tables the live panel uses (REMA/Dynamis-D path augments, Unity Concord ranks, JSE neck overlays), so a non-equipped REMA or Unity piece shows actual stats instead of a bare path letter (anything still unresolved falls back to the raw path). Separately, hovering a **food** in the food picker (the current selection or any open option) now shows a stat card built from the food's known bonuses (e.g. "Accuracy +50 / Attack +50 / Magic Atk. Bonus +35").

- **Sim food — percent/cap model, clickable BG-Wiki links, more foods** — the food picker gained six more options (Grape Daifuku +1, Coeurl Sub, Coeurl Sub +1, Carbonara with Store TP +6, Akamochi +1, Soy Ramen +1) and no longer caps the list at 11 — it shows all foods and the window grows to fit. The food data model now understands FFXI's real food math: a stat can be **flat** (e.g. STR +5) or **percent-of-base with a cap** (e.g. Accuracy +15%, max +72), and the lua resolves the percent against your pre-food stat and clamps to the cap — so a capped accuracy food correctly gives less on a low-accuracy build and tops out on a high one, instead of a fixed flat number. Seventeen of the nineteen foods are now verified-exact from in-game data / FFXIclopedia tables (only the base Akamochi and base Sublime Sushi remain on old approximate values). Several were badly miscategorized in the old flat data and are now corrected: **Soy Ramen**, **Yellow Curry Bun**, **Coeurl Sub**, **Red Curry Bun**, and **Akamochi** are *attack* foods (not the magic/acc mixes they were listed as); **Tropical Crepe** and **Pear Crepe** are *Magic Accuracy* foods (percent, not the Magic Atk. Bonus they had); **Marine Stewpot** is a flat AoE Acc/Ranged-Acc/Magic-Acc +90 food; and **Grape Daifuku**'s player effects are the small +10%/+11% acc-atk block (the "Pet:" line is pet-only). Newly added: **Yellow Curry Bun +1**. Every food name is a **right-click → BG-Wiki link**, and the two still-unverified foods show an **"(unverified)"** tag in their tooltip and keep the old approximate numbers until confirmed.

- **Sim buffs — new Blue Magic category (Erratic Flutter, Mighty Guard)** — the sim buff picker has a new top-level **Blue Magic** group for self-cast BLU buffs, starting with two. **Erratic Flutter** grants Haste II — +29.98% magic haste (307/1024). **Mighty Guard** adds +15% magic haste, **Regen +30 HP/tick** (shown in the panel's Regen cell), and **Defense +25%** — the defense bonus is applied as a multiplier on your *simulated* defense (gear + VIT + augments), the same way Chaos Roll's attack% multiplies simulated attack, so it tracks whatever defense your sim build produces. Mighty Guard's Magic Defense Bonus +15 isn't modeled (no panel cell), and it grants no Refresh (Regen only). Being a unique status it stacks with Haste and Embrava rather than overwriting. Both render as flat single-row entries in the sim window (no Plus/boost controls), matching the existing Spells bucket.

- **Sim EXPORT SET — real GearSwap format with augments** — exported sim sets now write a proper GearSwap-ready table: plain pieces as `slot="Name",` and augmented pieces as `slot={name="Name", augments={'DEX+20','Accuracy+20 Attack+20','"Store TP"+10',}},`, with the real augment strings decoded from each item's extdata (inner stat-name quotes preserved, e.g. `'"Store TP"+10'`). Slots use the conventional GearSwap names (`ear1`/`ear2`/`ring1`/`ring2`). This also fixes export for augmented picks outright — the old exporter predated the instance-ref equipment format and assumed every slot was a bare item id, so it errored on any augmented item and never emitted augments at all. Files still land in `…\addons\OmniWatch\simulation\export\` as `<CharName>_<timestamp>.lua`, ready to paste into a gear file (rename `sets.exported` to whatever you like).

- **Sim buffs — Geomancy: Indi-Precision + Bolster / Blaze of Glory toggles** — added **Indi / Geo Precision** to the sim's Geomancy buffs (Accuracy + Ranged Accuracy: +50/+50 at capped 900 skill, +5/+5 per Geomancy+ point, so Idris-tier "Plus 10" reads +100/+100). The two existing Geomancy entries are renamed to the dual **Indi / Geo Fury** and **Indi / Geo Haste** since the Indicolure and Geocolure forms share identical potency. All three now model **Plus as Geomancy+ points (0-10, Idris = 10)** consistently — and this corrected **Indi / Geo Haste**, whose per-point value was 5× too high (it was treating each Plus as a full ~5.5% Dunna step rather than one Geomancy+ point at 1.1%), so at Plus 10 it read ~85% magic haste instead of the correct ~41% (29.9% base + 11% Idris, matching BG-wiki's Eminent +3.3% / Dunna +5.5% / Idris +11% ladder). Every Geomancy buff now carries **Bolster** and **Blaze of Glory** toggles (the GEO equivalent of the BRD Soul Voice/Marcato row): each doubles the spell's potency including the Geomancy+ gear contribution, and per BG-wiki the two do not stack with each other — so ticking both is the same ×2 as ticking one, not ×4. Under the hood the sim's song-buff math gained an `extra_stats_scaled` path so Indi-Precision's ranged-accuracy half tracks the same Plus value as its accuracy half.

- **Sim buff — Embrava (SCH)** — added to the sim buff picker under **Spells**. Models Embrava at the 500-skill cap: +25.9% magic haste (266/1024), +25.9% Flurry (snapshot), **Regen +72 HP/tick**, and **Refresh +6 MP/tick** (the last two now surface in the panel's Regen/Refresh cells), all stacking into their buckets since Embrava is a unique status. This also taught the sim's spell buffs to carry extra stats — previously a `spell`-kind buff could only add one value, so Embrava's haste-plus-Flurry-plus-sustain bundle is the first to use the `extra_stats_flat` path.

- **Sim mode now drives the equipment panel** — opening sim mode takes over the EQUIPMENT panel so it shows exactly the gear you've picked in the Simulation window instead of your live set, with the title changing to **EQUIPMENT — SIM** while it's active. The panel is built straight from your sim picks on the Python side rather than waiting for the lua to echo gear back, so it reflects your choices reliably and instantly. It follows the same delta rule the stat compute uses: a slot you've set wins (an item, or "(empty)" to sim it unequipped), and any slot you haven't touched keeps showing your real gear — and since activation seeds every equipped slot, the panel mirrors your picks exactly. Hovering a slot shows the same full item card the live panel does (description, item level, jobs, augments) — it shares the sim window's tooltip builder, so an equipped piece shows its complete stats rather than just its augment tag. Closing sim mode restores the live equipment view untouched.

- **Sim mode item hover tooltips** — hovering an item in the Simulation window now shows the same rich item card the equipment panel uses, for both a slot's chosen item and any row in an open gear dropdown. When the hovered piece is the exact instance you currently have equipped, the card is the live equipment card verbatim — full augment strings (e.g. `Path A · Rank 15/15`, `"Double Attack"+5%`), description lines, item level, and jobs — matched by instance (bag/idx), so a different augmented copy of the same item shows its own short augment tag instead. The card follows the cursor and clamps to the screen edges, draws on top of the sim window, and is paused while the window is being dragged or resized. While the cursor is over the sim window the equipment-panel tooltip is suppressed so item cards from the panel underneath can't leak through. Respects the existing **show item tooltips** setting.

- **Hotbar hover tooltips** — hovering a configured hotbar button now shows a tooltip with the button's full label (bold) and its bound command underneath in grey, prefixed by kind (`//` for windower commands, `$ ` for shell) — so truncated labels in the small cells are readable at a glance and you can verify what a button fires before clicking it. The tooltip follows the cursor, clamps to the screen edges (flipping above the cursor near the bottom), draws at end-of-frame so it sits above every panel and modal, and is suppressed while a button drag is in flight and on empty cells. It shows whether panels are locked or not — lock stops panel dragging, not reading.

- **Hotbar button background colors** — each button can now have its own background tint, picked from a new **Color** row in the slot edit form: twenty presets — a muted set that sits quietly on the dark theme and a genuinely bright, saturated set for buttons that should stand out — plus a default chip (the slashed swatch) to return to the standard cell color. The swatch row wraps to extra lines when the panel is narrow or scaled down. Labels automatically flip to dark text on light backgrounds (bright yellow, light grey, etc.) so they stay readable on any swatch. Colors render as a translucent tint rather than solid paint — the chosen color is blended over the default cell at 70% strength so tinted buttons keep the dark theme’s depth instead of looking like pasted-on blocks.

- **BLU Spellsets editor — generated spell tooltips** — hovering a spell row in the edit view pops a themed tooltip (equipment-card style) showing type (Physical/Magical), target, MP cost, cast time, effects, elemental damage, skillchain properties, and proc sources, with cast and recast times shown together ("Cast 6s / Recast 60s"), and a spell’s set stat bonus (STR/DEX/MP etc., from the GearInfo spell table) shown under its own separator, each stat colored by sign (light green for a positive bonus, light red for a penalty), and the set cost / trait points in the footer below a final separator. ### Fixed
- **AoE buffs only showed the caster gaining the effect**: FFXI sends one action packet for an AoE buff where only the primary target carries a recognized "gains the effect" message; the other recipients arrive as a continuation (message 0) with the same buff param, which the status classifier rejected — so only the caster showed in the Buffs tab while the Battle tab correctly listed all targets. The buff synthesizer now does a two-pass scan: it captures the established status from any recognized apply in the packet, then propagates it to the other recipients that share the same buff param (or carry the continuation marker), without misclassifying AoE nukes as buffs.
- **Multi-target abilities not condensing**: "Mix" (Chemist) and other party-wide abilities are action category 11 (TP-move category), which wasn't covered by the multi-target condense pre-pass — they produced one "uses X → target" line per recipient. The condense pre-pass now covers categories 4 (magic), 6 (job abilities), and 11 (TP-move abilities), so party-wide Mix/Guard Drink/etc. collapse to a single line like AoE songs and ga-spells. Single-target mob TP moves are unaffected.
- **DPS reading low and slowly climbing**: the rolling-window DPS divided total damage by the full window length (e.g. 300s) instead of by the actual elapsed combat time, so the number started tiny and crept upward as the window filled — only correct after a full window of sustained fighting. It now divides by the real span between the first and last event in the window (capped at the window length, floored at 3s so the opening hit doesn't spike). DPS is meaningful within a round or two and then fluctuates around the true rate as gear/WS/buffs change.
- **Mob actions missing from chat**: high-tier monsters (Apex, Sortie/Odyssey/Aminon NMs) share the high entity-id range with players' trusts/pets, so the classifier tagged the mob you were fighting as "other_pet" — an actor class with no routing, so its actions silently vanished. - **Mob self-buff "uses" lines dropped**: a mob buffing itself targets itself, so neither side was an "ally" and the battle gate dropped the readies line — you saw the resulting buff on the card but never the "Apex Crab uses Bubble Curtain" line. The gate now also passes actions where the engaged mob is actor or target, so its TP-move use lines reach the feed. Other parties' fights stay hidden.
- **Healing/cure items shown as damage**: a trust's Mix/medicine (Max Potion restoring HP, Antidote curing poison) arrives on the TP-move category and was rendered as "→ target for N damage". HP-restore (message 238) now renders "recovers N HP" and status-cure/apply (message 159) renders with no damage trailer. Genuinely damaging items (e.g. Dark Potion) are unaffected.
- **Buff-gain line appeared before the "uses" line**: a mob TP move emits both a "uses ability" (combat) and "gains the effect" (status) line from one packet; they were emitted in the wrong order. The combat line now emits first, so chat reads "uses Bubble Curtain" then "gains the effect of Shell".
- **Stat panel color/formatting**: the always-yellow damage number and skillchain/mob colors were sorted out so each reads distinctly (see chat color notes).
- **Party-panel and timer debuff classification**: stat-down debuffs (STR/DEX/VIT/AGI/INT/MND/CHR Down, Attack/Defense/Evasion/Accuracy/Magic Def./Atk./Acc. Down) and Disease are now classified as debuffs (red, debuff column) rather than landing in the buff column.
- **Closing sim mode left stale stats on the panel**: turning sim mode off only flipped the data source but didn't force a recompute, and the live 1 Hz stats path only recomputes when a signature changes — so right after closing sim while idle (gear/buffs unchanged since before sim), the panel kept showing the sim values until something moved or you reopened the window. Closing sim now invalidates the live-stat signatures so the next tick fully recomputes and re-pushes your real stats and gear immediately.
- **Sim Import modal crash on paste**: pasting a path could crash the overlay with "A null character was found in the text" — the Windows clipboard returns UTF-16 with interleaved null bytes, and pygame's font renderer rejects any string containing a null. Paste now decodes UTF-16-LE correctly and strips null/control characters, and every dynamic string in the modal is sanitized at render time as a backstop.

- **Exit OmniWatch button**: Settings → General → "Exit OmniWatch" (top of section, labelled EXIT). Saves layout and buff state snapshot, then quits cleanly. Use this instead of force-killing the process so panel positions and buff durations survive to next launch.
- **Full Screen toggle**: Settings → General → "Full screen" (directly under Exit). One click fills the monitor the window is currently on at its full native resolution — including over the taskbar — with correct DPI scaling on any monitor (the process is per-monitor DPI aware). Click again to restore the previous size and position. Button label flips between FULL and RESTORE to reflect state. Combine with Always on top for a fullscreen overlay over the game.

### Changed
- **Window is always borderless**: OmniWatch no longer has an OS title bar at any point. Previously borderless mode was a runtime toggle (Settings → General → "Borderless window") that defaulted off and snapped fullscreen on; now the window starts borderless, stays borderless for the entire session, and the toggle is gone. Move the window by holding Shift and dragging anywhere inside it (same as 1.2.x borderless mode). Resize via Full Screen toggle (above) — there are no edge handles. Quit via the Exit button in Settings (no OS [X]).
- **Settings menu reorganization**:
  - **Inventory section renamed to Header** and moved to right under General. The settings in it (Show 'Bags' button, Gearswap folder) are header-row widgets, and grouping them with the other header items (clock offset, zone-timer reset) makes the mental model clearer.
  - **Adjust Vana'diel time** moved: General → Header.
  - **Reset zone timer** moved: General → Header.
  - **Open log folder** moved: General → Developer (it's a debugging tool, not an everyday setting).
  - New section order: General → Header → Party → Equipment → Statistics → Recast Timer → Buff Timer → Target Card → DPS Tracker → HotBar → Developer.

### Removed
- **Borderless window setting** (`borderless_window` in settings.json): made unconditional, so the toggle is gone. Stale keys in upgraded settings.json files are ignored harmlessly.
- **Per-mode panel layouts** (`window_mode_layouts` in omniwatch_layout.json): the framed-vs-borderless layout-swap mechanism is gone since there's only one window mode now. Stale keys in upgraded layout files are ignored harmlessly. Your current panel positions are preserved — only the (unused) secondary slot is dropped.


## [1.2.0] — 2026-05-12

### Added
- **Customizable stats panel layout**: hide cells you don't need and drag cells to any position. Settings stored per-character and per-job. Two scopes:
  - **Global hidden**: cells hidden everywhere, on every job. Use for stats you never want to see.
  - **Per-job hidden**: cells hidden only on that specific job, additive on top of global. Use for stats irrelevant to a specific role (e.g. MAB on COR).
- **Setup-mode stats panel UI**: enter setup mode (`//ow setup`) to edit the layout interactively.
  - Click any cell to toggle hidden (dimmed in place with a red slash)
  - Drag cells anywhere to reorder — drag freely across the entire panel
  - Hidden cells appear as clickable chips in a tray below the panel; click a chip to restore
  - "Save as ▼" dropdown commits your edits to Global, Current Job, or any specific job
  - Edits are in-memory until saved — exiting setup mode without clicking "Save as" discards changes
- **Linear-flow uniform-cell layout (v2.0)**: stats panel rebuilt around a uniform 7-column grid where any cell can occupy any slot.
- **"Empty" spacer cells**: 4 invisible spacer cells (`_empty1`–`_empty4`) that can be dragged anywhere to create deliberate gaps in the layout. Visible only in setup mode; truly invisible during normal play.
- **JSON-edit fallback**: Settings → Statistics → "Edit stats layout" opens `omniwatch_stats_layout.json` directly for power users who prefer editing config files.
- **Resist cell redesign**: now shows active elemental resists as compact color-coded text (e.g. "Fire+25" in red, "Ice+15" in blue) instead of icons. Fits in a uniform-size cell alongside other stats.

### Changed
- **Stats panel architecture (v2.0 refactor)**: the prior section-based layout (Primary, Haste, Defense, etc., each with fixed dimensions) has been replaced with a unified flat ordering. Cells are all the same width now; the previously-wider elemental cells use compact labels.
- Backward compat: existing v1.1 saved layouts (per-section dicts) are auto-flattened to the new linear order on first read. Your hides and ordering are preserved.

### Fixed
- **BLU job crash (`attempt to perform arithmetic on local 'v' (a table value)`)**: switching to BLU could crash when computing trait points. The trait-summation loop didn't account for non-trait metadata fields (`vitals`, `id`, `level`) in BlueMagic.lua entries; now those are explicitly skipped, and only numeric values are summed. Also fixes silent corruption of trait totals that may have been ongoing before the crash.
- **Trust Primer / food crash (`attempt to call global 'ow_parse_desc_line' (a nil value)`)**: using a consumable item could crash the addon due to a forward-reference issue — the function was declared `local` after the closure that referenced it, so the upvalue resolved to nil at call time. Forward-declared the local so all consumers share the same slot.
- **Stats layout not persisting between sessions**: saved layouts weren't being read on subsequent launches. The load was being skipped because of a startup shortcut that runs when the character pre-selection heuristic guesses correctly. Added a deferred load call right before the main loop so layouts always load regardless of which startup path fires.


## [1.1.0] — 2026-05-11

### Added
- **Borderless window mode**: hide the OS title bar for a cleaner look. Toggle in Settings → General → "Borderless window". With borderless on, hold Shift and drag anywhere in the window to move it. Maximize state is preserved when toggling. Setting persists across sessions.
- **Show party toggle**: hide the entire main party panel (your character + party members) for solo play. Toggle in Settings → Party → "Show party", right above the existing "Show alliance" option. Independent from the alliance toggle.

### Fixed
- **Buff timer accuracy**: timers now reflect server-truth expiry, matching Windower's built-in Timers display. Reads the 0x063 sub-9 packet directly using an empirically-verified epoch formula for current FFXI. Songs, rolls, Refresh, food, and every other buff (including ones cast on you by other players) now show the correct remaining time.
- **Buff bar "snap to 100%" on wear-off**: when a buff wore off in one slot and FFXI compacted remaining buffs into lower slots, the affected bars would visibly reset to full. Now tracks each buff's identity across slot migrations so fullness ratios stay continuous.
- **Buff timer persistence across Python reloads**: closing and reopening the OmniWatch overlay no longer loses timer fullness. Lua sends absolute Unix timestamps for buff expiry, and Python additionally saves state to `omniwatch_buff_state.json` between sessions. Bars come back correct after restart.
- **Cleaned up leftover debug chatter**: cleaned debug chatter that presents itself when casting or using ability

### Changed
- Buff timer wire format bumped to v3 with absolute timestamps (backwards compatible — older Python overlays still work with newer Lua, just without the persistence benefit).


## [1.0.0] — 2026-05-09

Initial public release.

### Added
- Party panel with HP/MP/TP, jobs, buffs/debuffs, pets, and optional alliance support
- Target & sub-target cards with mob family info, abilities, resists, BG-wiki imagery
- Player target cards with race + sex icons
- Equipment viewer for all 16 slots with extracted icons and rich tooltips
- Recast tracker (magic + abilities) with auto-hide and color-shifting bars
- Buff timer panel with wear-off flash
- DPS tracker with rolling-window display, sparklines, and CSV/JSONL logging
- Stats panel computing Acc/Att/RAcc/RAtt/Def/Eva/MAcc/MAB/etc. from gear + buffs + traits
- BLU spell-trait math with JP gift bonus handling
- Hotbar (button panel) with custom icons and right-click actions
- Inventory dropdown across all bags with GearSwap reference detection
- Header strip with Vana'diel clock, zone, and character switcher
- Sim mode for what-if calculations on jobs, gear, songs, rolls
- Server_Stats.lua passive listener for server-pushed Att/Def/Acc updates
- Setup mode (`//ow setup`) for laying out panels with mock data

### Known issues at release
- Lanun gear roll-proc accuracy may not always reflect the boosted value (server doesn't reliably push the relevant packet)
- Running multiple FFXI clients with OmniWatch on the same machine is not supported (UDP port collision). Single-client multi-character config support via the character dropdown works normally.
- Some BLU JP-category linear bonuses for MAB/MAcc are not yet wired through
